      A data source changes how, never what

      CLI and API both answer "how much of my limit is left". A choice in that list that answers a different question breaks the menu bar and the card.

      Activity goes with activity

      Desktop's count is tokens used today, like the Claude Code token card. It belongs in the same Today section, labeled with where it came from.

      Say what's missing and what to do

      Without Claude Code there are no limits to read. The card says so and offers the next step, instead of an error or an empty menu bar.

      This Mac's app, not a login

      The file belongs to Claude Desktop on this Mac. It shows once, on the usual login, and never under an added account.

      The JSON

      It goes in Claude's existing usageHistory. Desktop's file reuses the reader usageHistory already has: format: json is one record per file, and tokens.total is for a log that keeps only the sum. Added logins drop it through the patch they already have, because the file belongs to the Mac, not a login. No prices, so the card shows tokens and no cost.

      // claude.json "usageHistory": { "records": { …Claude Code, unchanged… }, "prices": { "file": "claude-prices.json" }, "freeWhen": { … }, "sessionGap": 1800, "otherApps": [{ "label": "Claude Desktop", "records": { "files": "~/Library/Application Support/Claude/buddy-tokens.json", "format": "json", "at": { "field": "$.tokens-today.date", "format": "yyyy-MM-dd" }, "tokens": { "total": "$.tokens-today.tokens" } } }] }, "accounts": { "patch": { "usageHistory": { "records": { "files": "{{account.configDirectory}}/projects/**/*.jsonl" }, "freeWhen": { … }, "otherApps": null // merge-patch null removes it: the Mac's app shows on the usual login only } } }

      Two general rules in DataSources, neither of which names Claude:

      // 1. "at" can read a field with a format, like fromPath does. Local time unless "timeZone" says otherwise. // "2026-05-28" is the user's day; ISO8601Instant alone can't read it, so today the record is dropped. // 2. An otherApps entry whose files aren't found shows no card. A file dated yesterday is just yesterday's // record, so today reads 0 ("Not used yet today") with no special case.
